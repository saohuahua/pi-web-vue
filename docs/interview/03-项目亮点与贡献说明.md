# 项目亮点与贡献说明

项目能力、个人贡献和效果证据是三个需要对齐的层次。源码可以证明系统存在某种机制，却不能仅凭函数存在就证明它由谁设计，也不能推出节省了多少时间。本篇帮助把已经理解的技术事实转成准确、可被追问的项目表达。

## 先确定介绍主线

这个项目适合定位为前端主导的 Agent 应用集成：浏览器展示和交互占主要体验，Node 服务托管 SDK 并访问本地文件。技术栈包括 Vue 3、Nuxt 4、TypeScript、Pinia、Tailwind CSS、SSE、Node.js 与 pi SDK，但介绍不应只是把这些名称连起来。

可以先使用下面的概括，再补真实个人职责：

> 面向开发者的本地 Web 编程工作台，通过 Node 服务托管 pi SDK 会话，以 HTTP 命令与 SSE 事件连接 Agent 运行过程和浏览器 UI，支持流式对话、工具可视化、会话恢复、文件预览和能力配置。重点处理持续执行中的状态组织与前端交互。

这段说明产品形态和核心链路，面试官容易继续问“状态怎么组织”或“恢复到什么程度”。完整分支、MCP 和自定义检索工具尚无闭环依据，不适合作为开场已完成能力。

## 从功能描述转成工程亮点

“做了 SSE”和“用了 reducer”只说出了工具。更完整的表达要说明对象有什么变化、为什么需要这个机制，以及代码能够支持什么结果。下面是项目级候选表述，使用时把动作归属改成真实的实现、移植适配或参与改造。

- **全链路集成：** 面向浏览器操作持续运行的 Agent，在 Nuxt 服务端托管 SDK 会话，以 HTTP 提交命令、SSE 接收运行事件，通过业务握手和预检确认区分订阅就绪、命令接受与执行完成。
- **流式状态管理：** 针对文本、思考和工具交错输出，将完整消息、当前草稿和活跃工具分开维护，使用 reducer 按内容块组装，再按调用 ID 关联结果，形成可独立验证的数据变换。
- **连接与状态恢复：** 通过历史加载、当前快照和旧响应检查处理页面恢复与切换，并维护连接重试；自动重连后的完整历史对账仍需补齐，不使用无损恢复表述。
- **事件传输适配：** 去掉增量中的重复全文快照，同时保留工具元数据，使浏览器能够处理较小的增量结构；性能收益另用固定样本测量。

如果篇幅有限，可以把传输适配放进全链路集成下解释，不必把同一个事件机制拆成多条看似不同的亮点。状态管理适合展开前端能力，实例和协议适合说明服务集成，两者共同构成项目主线。

## 参考实现与个人工作怎样区分

SDK 提供模型与工具循环，pi-web 提供了部分已移植的 reducer、连接和事件处理逻辑，本项目再接入 Vue、Pinia、Nitro 和工作台组件。来源关系见 [THIRD_PARTY_NOTICES.md](../../THIRD_PARTY_NOTICES.md)。

移植后的工程工作可以有价值，但要落到实际变化。比如普通对象引用进入 Vue 响应式代理后是否仍可直接比较，路由卸载会不会关闭新会话，Markdown 改成 HTML 渲染后如何处理复制交互，这些都是适配需要面对的问题。说明清楚判断与验证，比将全部底层算法称为原创更有说服力。

个人经历需要补充的事实可以集中整理：

- 哪些模块本人编写，哪些原样移植，哪些在参考基础上修改。
- 遇到过什么可复现现象，怎样找到具体状态或时序原因。
- 实际改了什么，使用哪些测试或操作证明结果。
- 是否有真实使用、耗时或性能记录，以及测量范围。

当前发现的代码缺口只能作为分析材料。除非本人确实处理并完成验证，不把它改写成“我当时遇到并解决了”。

## 一段经历如何讲得具体

以会话切换为例，“修复了竞态问题”还没有说明技术过程。完整叙述需要明确旧请求怎样覆盖新状态、判定条件放在哪里，以及验证怎样控制返回顺序。下面是组织方式，不是已经确认的个人经历：

1. 先交代可观察现象，例如切到 B 后页面又显示 A 的消息。
2. 再说明证据，例如 A 详情比 B 更晚返回，并直接写入共享 store。
3. 解释修复范围，例如提交响应前检查会话身份，并进一步考虑操作代次。
4. 最后给出结果，例如在确定的 A→B 延迟用例中最终仍显示 B；没有覆盖的 A→B→A 另列验证。

口头讲述不必把这四项生硬念成清单，它们是叙述必须包含的信息。不要把“加了判断”替代根因，也不要把一个用例通过扩大成所有竞态都解决。

## 结论要与证据对应

能说明 preflight 后返回，不代表所有命令都短请求；有当前快照，不代表服务重启后能继续执行；有本地文件授权，不代表整个 Agent 处于安全沙箱。恢复、权限和性能都需要明确对象及边界。

对于没有量化数据的结果，可以说“将完整消息与流式状态分开”“命令确认无需等待完整生成”，这些是可检查的行为变化。不要直接补上降低多少延迟、提升多少效率。将来有测量时，补充工作负载、对比基线和环境即可。
