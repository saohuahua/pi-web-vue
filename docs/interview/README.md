## 每个问题怎么组织回答

主问题按六段组织，**结论永远在第一句**。简单问题只用第 1、6 段，不要机械地把六段全说一遍。

| 顺序 | 这一段说什么 | 常见错误 |
| --- | --- | --- |
| 1 核心结论 | 30 秒能说完的明确回答 | 先讲背景，结论藏在最后 |
| 2 为什么 | 业务约束、方案比较、取舍 | 只讲“这样更好”，不说代价 |
| 3 如何实现 | 关键模块与数据流，能报出文件或函数名 | 只讲思路，落不到代码 |
| 4 怎么验证 | 明确验证了什么、**没验证什么** | 用“应该没问题”代替证据 |
| 5 连续追问 | 至少覆盖一个“为什么不用 X”和一个“如果再做会怎样” | 把追问当成新问题重讲一遍 |
| 6 一句边界 | 当前方案的缺陷或部署限制 | 结尾把方案说得没有缺点 |

> 通用的收尾句式：**“当前实现覆盖到……，还没有覆盖……，要继续做需要先……”**。凡是没做的东西主动说出来，比被追问出来强。

## 按用户操作串联知识

| 用户操作 | 先理解的处理 | 接着准备的追问 |
| --- | --- | --- |
| 带图发送，等待时又加一张图 | 本批输入快照、成功后定向清理 | 为什么浅拷贝够用；Vue 代理怎样影响对象比较 |
| 输出一半刷新 | 历史、当前快照、事件分别恢复什么 | 查询与订阅之间结束怎么办；为什么重连不等于续传 |
| A 切 B 再回 A | 会话 ID、生命周期代次、请求序号 | 为什么取消请求不能替代写回守卫；finally 是否也要检查 |
| 发送失败后继续输入 | 待确认文本、草稿合并、按会话保存 | localStorage 失败怎么办；为什么恢复后不能自动重发 |
| 修改旧问题再发送 | 父记录定位、导航、权威回读和回退 | 只改数组为什么不够；位置未知时为什么禁止发送 |
| 运行中追加，然后点停止 | SDK 队列、接纳顺序、撤回再 abort | 为什么只串行接纳；多窗口是否仍可能插入命令 |
| 打开模型生成的文件链接 | 路径规范化、目录边界、真实路径 | 前缀目录和符号链接怎么处理；预览边界与执行隔离区别 |
| 长代码回答越来越卡 | 传输、状态组装、解析、DOM 和布局 | 缓存、按帧合并、Worker、虚拟列表分别解决什么 |

## 一组完整的练习

从“刷新还能接上吗”开始，连续回答下面六问：

1. 刷新丢了哪些状态，服务端还有哪些状态？
2. 已完成历史和正在输出的一条消息分别从哪里恢复？
3. 历史读完、事件订阅之前，任务恰好结束会怎样？
4. 重连时没有新事件，怎样知道任务已经完成？
5. 历史请求比新事件晚回来，为什么会覆盖新数据？
6. 引入快照游标和事件序号后，重复事件、日志过期、进程重启分别怎么处理？

答案分布在 01 的恢复主线与 04 的核心实现思路和实验中。练习时先画出先后顺序，再解释每个判断保护什么，最后补替代方案的成本。

## 实现与证据说明

主要五篇按 2026-09-28 当前工作区核对，包含已有未提交代码。历史演进根据实际代码变化整理；文中明确标注的后续方案尚未实现。引用块提供技术回答，个人职责按真实参与范围补充。

本次运行发送、队列、异步交错、草稿、服务端包装器、事件流、reducer 与事件裁剪相关测试，共 **8 个文件、64 条测试通过**。测试基于当前工作区，不等于真实断网、浏览器滚动、多窗口操作或服务重启已完成端到端验收。当前没有可用于宣称性能提升比例的测量数据。
