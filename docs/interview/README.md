# 项目面试准备：先拿 P0，再补 P1/P2

**时间有限就只过 P0 八类问题。** 这份目录按面试价值排序，不是按文章顺序；每一类都指向**唯一的主讲位置**，同一个机制不会在多篇里重复展开。

> **需要按简历逐条深挖时，进 [pi-web-vue 深挖文档](pi-web-vue/README.md)。** 本目录回答「先准备哪几类」，那份回答「简历上每句话对应哪段代码、追问到第几层会露馅」，两者不重复。

## 这份文档怎么用

| | 学习篇 `docs/learning/` | 面试篇 `docs/interview/` |
| --- | --- | --- |
| 回答什么 | 机制是什么、为什么需要、代码怎么实现、时序怎么变化 | 面试官会问什么、先给什么结论、追问时再深入哪里 |
| 怎么读 | 按主线顺序读到能自己讲 | 按优先级筛选，练口述 |
| 深度 | 负责讲透原理 | 负责提炼表达与取舍 |

三档优先级各自什么时候用：

- **P0（8 类）**：必须能独立回答。即使只剩很少准备时间也先过这些，每类都能直接照读。
- **P1**：常见深入追问。理解设计理由与代价就够，**不要求把每个异常分支都背成完整答案**。
- **P2**：查到即可。变量、常量、低频 API 比较、未落地的优化方案，都在各篇末尾的「**深入参考（P2）**」区，不作为默认复习任务。

> **标记怎么读：** 优先级写在本篇的小节标题末尾。`##` 标这一节的主级别；`###` **只在级别与父级不同时才标** —— 例如 [01 §2](01-项目介绍与架构表达.md#2-通信方式为什么拆成-http-命令和-sse-事件-p0) 是 P0，它下面两个追问标 P1，其余继承父级、不再重复标注。
>
> 学习篇用的是另一套「必读 / 进阶 / 了解」，那是**篇目级**的，回答“先读哪几篇”，与这里的问题级 P0/P1/P2 不需要互相换算。

## 推荐复习路线

1. 先读学习篇的**必读八篇**，建立机制理解（入口见 [学习目录](../learning/README.md)）。
2. 过一遍 P0 八类，每类先只练「核心结论」那一句，能独立说完再往下。
3. 用下面的自测题检查，答不上来的回 P0 主讲位置补。
4. 按答题缺口补 P1 的主题，不需要逐篇读完。
5. P2 只在被追问到具体细节时查，不要提前背。

**不要做的事：** 按文章顺序逐篇通读；把每个异常分支都准备成完整答案；背常量与提交号（那些是回答里用来佐证的证据，不是答案本身）。

## 面试自测（8 问）

不看文档，试着连续回答完。这组题串的是项目理解、业务判断、方案取舍和证据意识。

1. 如果只用 1 分钟介绍项目，你会怎么介绍？
2. 用户发出一句话之后，完整调用链是什么？
3. 为什么浏览器不能直接持有 Agent SDK 会话？
4. 为什么流式消息需要结构化状态？
5. 用户切换会话后旧请求才返回，怎么保证当前页面不被污染？
6. 项目最难的问题是什么，方案是如何演进的？
7. 如何证明你做的改动有效？
8. 如果继续做，下一步优先级是什么？
