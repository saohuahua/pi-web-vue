## 项目学习

**从 [项目学习入口](learning/README.md) 开始。** 那里给出 22 篇正文的 **必读 / 进阶 / 了解** 分级、三条不同起点的阅读路线，以及跨篇统一的术语表：会话 / 一次执行 / 消息 / 记录、SDK 事件 / wire 事件 / 前端状态、工具 / 扩展 / 技能 / 插件包 / MCP、重连 / 快照恢复 / 事件重放 / 历史回读。

**熟悉前端、略懂后端，想先弄清功能怎样运转：读 [业务流程与前后端协作](learning/业务流程与前后端协作/README.md)。** 六篇从创建任务、运行中追加、停止、恢复、文件和配置入手，串起浏览器、后端、SDK 与模型的处理过程。

需要通过最小代码理解 SDK 接入时，读 [从最小 Agent 到 Web 工作台](learning/00-从最小Agent到Web工作台.md)。之后按具体功能进入技术专题。

推荐学习顺序：先在业务篇理解操作规则，再沿正文链接进入技术专题，最后用测试和面试问题检验理解。完整衔接路线见 [业务、实现与验证的三个贯穿场景](learning/业务流程与前后端协作/README.md#用三个场景贯穿业务实现与验证)。

1. **跑通主线**：认识 SDK → 最小 Node 程序 → 网页输入输出 → 流式回答 → 工具执行与展示。
2. **理解任务管理**：工作区与会话 → 服务端实例 → 历史和上下文。
3. **深入前端核心**：HTTP 与 SSE → 消息状态与渲染 → 异步协作与恢复。
4. **扩展工作台**：文件访问与预览 → 模型配置与能力中心 → 验证方法。

总览用于查看产品范围，SDK 补充篇用于查会话和资源概念，工程结构篇用于定位代码。其余专题按需要进入，不要求第一遍按编号全部读完。

> 各篇先说明目标与约束，再推导设计决定，随后用数据、关键代码和前端表现解释如何落地。教学演进不代表真实开发历史，改进建议不代表已实现功能。

阅读代码时重点看：为什么需要这个判断、await 前保存了什么、结果返回后何时允许提交，以及失败与清理分支保护了什么。复杂关系使用本地 SVG，可单独打开和放大阅读。

## 面试准备

**从 [面试阅读目录](interview/README.md) 进入。** 面试篇按 **P0（必须能独立回答）→ P1（常见深入追问）→ P2（查到即可）** 三级组织。时间有限就先过 P0，再按答题缺口补 P1/P2。

需要**按简历逐条深挖**时，读 [pi-web-vue 项目面试深挖文档](interview/pi-web-vue/README.md)：把简历三条 bullet 逐句映射到源码，明确区分 SDK 能力、pi-web 移植模块、本项目改写与未实现能力，并标注每项结论的证据等级（源码确认 / 测试覆盖 / 静态推导 / 待核实）。

1. 用 [01 项目介绍与架构表达](interview/01-项目介绍与架构表达.md) 准备 1 分钟项目介绍、完整调用链与下一步优先级。
2. 用 [03 项目亮点与贡献说明](interview/03-项目亮点与贡献说明.md) 准备一段能展开的项目经历与最难问题。
3. 用 [04 验证方案与源码索引](interview/04-验证方案与源码索引.md) 回答“怎么发现问题、怎么验证、测试证明到什么程度”。
4. 用 [05 前端流式对话](interview/05-前端流式对话实现与优化.md) 回答前端状态、渲染与性能追问。
5. [Agent 架构与选型对比](interview/agent-comparison/README.md) 属于**扩展阅读**，不作为默认准备步骤。

回答中的改进方案不等同于已经完成的个人经历。面试篇与学习篇的职责分工见 [面试阅读目录](interview/README.md)。

- 项目说明不预设个人贡献；面试中的经历、职责和指标需要真实材料支持。简历表述与源码证据的对应关系见 [面试篇 03](interview/03-项目亮点与贡献说明.md)，**个人贡献归属仍需作者本人确认**。

- UI 设计规范仍以 [DESIGN.md](../DESIGN.md) 和 [design](../design/) 内的契约为准。
- 分支 草稿和运行中队列的原始规格及当前验收边界见 [功能改进实施规格](../vue-agent-plan/14-feature-improvement-spec.md)。
