## 用三个场景贯穿业务、实现与验证

**发送后很久没有回答。** 从 [B02 的业务握手](B02-创建会话到完成一次任务.md#四-业务握手连接建立不等于已经能接收任务事件) 判断卡在订阅准备还是命令接纳，再读 [协议篇的握手等待](../05-HTTP与SSE协议.md#四-先完成业务握手-再发-prompt) 和 [服务篇的接受确认](../04-Agent服务与生命周期.md#五-接受任务和完成任务-为什么是两个-promise)。最后用 [可控异步测试](../11-测试体系与验证边界.md#三-异步测试-先控制时间顺序) 区分“尚未接纳”与“已接纳但执行未结束”。

**切换后旧内容又出现。** 先读 [B04 的会话代次](B04-历史恢复与编辑重发.md#九-切走再回来为什么旧请求仍要作废)，再对照 [B05 的文件加载](B05-文件浏览与执行目录.md#五-快速切换文件为什么旧内容不能写回来) 和 [B03 的队列版本](B03-运行中追加与停止.md#五-为什么队列查询还要检查版本)。它们都拒绝过期写回，但失效原因分别是会话重新打开、文件重新加载和队列收到新事件。用 [倒序返回测试](../11-测试体系与验证边界.md#四-旧请求测试-要故意让结果倒序到达) 检查内容、错误与加载标记，而不只检查当前名称。

**保存成功，但页面还显示未保存或旧模型。** 从 [B06 的保存期间继续编辑](B06-模型配置与能力加载.md#保存期间又改了一个字段怎么办) 判断未保存标记是否合理，再读 [配置篇的提交快照](../10-模型配置与能力中心.md#保存返回时-怎样保留请求期间的新编辑) 与 [缓存及运行生效](../10-模型配置与能力中心.md#六-保存后-为什么列表与运行实例不一定立即一致)。这条路径把用户新输入、正式文件、列表缓存和当前会话串起来，能定位究竟哪一层还没有更新。

理解流程和验证方式后，再用 [面试异常追问](../../interview/04-验证方案与源码索引.md) 检验能否解释反例，用 [功能迭代案例](../../interview/03-项目亮点与贡献说明.md) 组织方案为什么变化的回答。

本组按 2026-09-28 当前工作区核对，包含尚未提交的实现。每篇已分别审读功能顺序、状态来源、异常处理和表述，再核对源码。文中的示例用于解释流程，不表示真实运行记录；后续方案与现有行为在对应位置区分。
